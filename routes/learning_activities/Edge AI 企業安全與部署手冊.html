ENTERPRISE EDGE AI · SCIENTIFIC AGENT SECURITY

企業級 Edge AI 自主智慧體
與縱深安全防禦指南

整合 NemoClaw／OpenShell、NeMo Guardrails、AI Gateway、GROMACS、MCP 與 Palo Alto Prisma AIRS 的可執行安全架構。核心原則是：模型負責推理與規劃；政策、身份、沙盒與可驗證工具負責決定「能不能做」。

重要校正與補強

已將原始筆記的概念保留，並修正容易造成部署誤解的地方；正式採購、對外簡報或合規文件仍應以當下原廠版本、授權條款與實測數據為準。

原始敘述 建議修正 原因／落地方式
「NemoClaw 是自主研究大腦」 NemoClaw 是在 OpenShell 沙盒內部署與操作相容 Agent 的參考整合／生命週期工具；LLM、Agent framework、工作流與工具才共同構成「大腦」。 避免把部署與治理層誤寫成單一推理模型。將模型、Orchestrator、Skill、政策與狀態機分別標示。
「NeMo Guardrails 在 Gateway 端攔截且不消耗 LLM 算力」 部分規則可用字串、分類器或政策引擎執行；但某些 Guardrails 流程可能仍需呼叫模型或額外推論。 安全設計需做延遲與成本預算，不能假設所有 Rail 都是零成本。
「所有流量都通過 Portkey」 AI Gateway 應收斂 LLM 與 Agent API 流量；GROMACS 的 MPI／RoCE 資料面不應硬經 API Gateway。 控制面經 Gateway；HPC 資料面走受控叢集網路與 Scheduler，避免性能與可靠性問題。
「MCP 可讀寫 HR／GitLab／Jira」 預設唯讀；寫入／部署／刪除等動作必須用最小權限、結構化參數、短效授權與人工核准。 避免過度自主性與 LLM 直接造成不可逆企業操作。
「AI 自我進化，自動上架 Skill Bundle」 成功軌跡可被記錄、評估與候選化；進入正式 Skill Library 前需測試、簽章、審核與可回滾發布。 防止模型把錯誤、偏誤或受攻擊軌跡自動固化為生產能力。
「單機／四機原子數與互連效能」 列為研討會案例或待驗證基準，不作通用容量承諾。 GROMACS 擴展性受系統拓撲、MPI、網卡、domain decomposition、記憶體、力場與 I/O 影響，必須以目標工作負載 benchmark 驗證。

目標軟體架構

[Researcher / Employee / Open WebUI] │ OIDC / MFA / TLS ▼ [AI Gateway: auth · routing · quota · DLP · audit] │ ▼ [Guardrails / Policy: input · retrieval · dialog · execution · output] │ ▼ [Agent Orchestrator: state machine · plan · approval · retry] ┌──────┴───────────┐ ▼ ▼ [RAG with ACL] [Skill Router] │ │ ▼ ┌───────┴────────┐ [Trusted KB] ▼ ▼ [GROMACS Sandbox] [HR/GitLab/Jira MCP] │ │ [HPC Scheduler / MPI] [Scoped internal APIs] │ [Artifact + Result Store]
責任切分：Gateway 處理身份、流量、模型路由與審計；Guardrails／OPA 類政策層判斷內容與動作；Orchestrator 管理狀態與審批；Sandbox 與 Scheduler 實際執行受限任務；RAG 僅提供有權限的證據。

任務生命週期

01

任務提交與身份綁定

使用者透過前端提出研究或行政需求。Gateway 以 OIDC／JWT 驗證身分、部門、角色、設備狀態與資料分級；每次請求產生 correlation ID。

02

輸入與檢索安全判斷

執行 Prompt Injection、敏感資料與內容長度檢查；RAG 在檢索前先依 ACL 過濾，並把文件內的「指令」視為不可信資料，而非可執行命令。

03

規劃與風險分級

Agent 產出結構化計畫：工具、資料集、預估資源、輸入參數、預期輸出與風險等級。高風險行為必須停在 approval gate。

04

政策准入與安全執行

Tool Router 驗證 JSON Schema、allowlist、ABAC、短效 capability token 與 sandbox policy；核准後由 GROMACS／MCP Sandbox 執行。

05

結果驗證與可追溯輸出

解析器驗證結果格式、數值範圍、輸出檔雜湊與引用來源。LLM 只能根據已驗證結果撰寫摘要，不能自行捏造模擬結論。

06

審計、候選技能與回饋

保存請求、政策決策、模型版本、工具版本、輸入雜湊、結果與人工核准。成功軌跡只進入「候選技能」；測試與審核通過才可發布。

AI Gateway 專章

AI Gateway 是 LLM 與 Agent 控制面的單一入口，不是單純反向代理。它將所有模型請求轉為可身分化、可配額化、可審計化與可施行資料政策的操作。

Identity

驗證與授權

使用者採 SSO/MFA；服務使用 mTLS、Service Account 與短效 Token。授權採 RBAC + ABAC，例如限制資料部門、用途、工具與有效期限。

Routing

模型與資料路由

依資料級別、模型能力、成本、健康度與延遲導向地端或已核准後端；機密資料不得因 fallback 自動送往外部模型。

Budget

資源與成本防護

控制 RPM、TPM、並發、queue depth、最大 context、輸出 token、timeout 與每部門預算；避免 DoS、GPU/RAM 耗盡與帳單失控。

Audit

日誌即證據

記錄 actor、application、model、policy、資料分類、RAG 文件 ID、tool call、結果摘要、風險旗標與 correlation ID；敏感原文需遮罩或受控保存。

Gateway 與 HPC 的界線

控制面 ≠ 資料面：使用者請求、模型推論、工具申請、審核與稽核經 AI Gateway。GROMACS 跨節點 MPI、RoCE、checkpoint I/O 和 scheduler 內部通訊屬 HPC 資料面，應由叢集網路隔離、Scheduler ACL、檔案系統權限與監控控制，而非全部穿越 HTTP API Gateway。

NemoClaw、OpenShell 與 Agent 治理

NemoClaw

部署與生命週期整合

將它定位為在 OpenShell 受控 Sandbox 中運行相容 Agent 的參考堆疊與操作工具；避免將其等同於單一模型、通用科學推理引擎或自動學習平台。

OpenShell

宣告式最小權限

將檔案、網路、程序、二進位與憑證權限寫成政策；每個 Sandbox 僅能取得任務必要權限，並保留可匯出的執行記錄。

Approval

人類核准閘門

提交大規模模擬、寫入企業系統、下載資料、外部連線、修改 GitLab 或發送郵件都需依風險等級進入人工核准。

Skill Lifecycle

技能發布治理

Skill 須有 owner、版本、SBOM、測試、最小權限政策、授權範圍與退役日期。成功軌跡先成候選，不可自動升級生產能力。

GROMACS 科學工作流安全化

科學 Agent 的目標不應是「自行下結論」，而是產出可重現、可檢查、可審核的實驗計畫與模擬 Artifact。GROMACS 可用 checkpoint 支援中斷後續跑，但可重現性仍需保存完整的版本、參數、輸入與硬體／軟體環境。

階段 Agent 可做 必須由系統強制
假設生成 根據核准文獻與材料資料提出候選配方、模擬目標與比較指標 標示證據、限制範圍，不可宣稱未經模擬驗證的物理結論
參數建議 生成候選 mdp／拓撲／作業描述 Template allowlist、單位／範圍檢查、force field 與版本鎖定、人工 review
作業提交 提出資源估計與 job spec Scheduler quota、partition、時間／CPU/GPU/RAM 上限、資料集 ACL、核准流程
執行與續跑 讀取受控 status、建議 retry 或 checkpoint restart 唯讀狀態 API、checkpoint 完整性、禁止任意 shell、失敗上限與成本上限
分析與報告 根據已驗證結果生成圖表說明與摘要 解析器驗證數值與檔案雜湊；報告標示模型、誤差、seed、版本與重現命令

TIM 與 Blackwell 案例的正確寫法：可作為「研討會展示／概念驗證案例」描述。不要將特定原子數、四機串聯、互連頻寬或效能增益寫成通用保證；應改附你自己的 system topology、GROMACS version、input system、benchmark 命令、wall time、scaling efficiency 和重現 Artifact。

將 GROMACS 與 MCP 封裝為安全 Skill

禁止：將使用者自然語言或 LLM 產出的任意檔案路徑、Shell 片段、URL、SQL、Slurm 指令直接傳給容器或 HPC Scheduler。

安全 Skill 介面原則

  • 以具版本的 JSON Schema 接受 job template、資料集 ID、資源級別與已核准參數，而非自由文字命令。
  • 以 allowlist 選取容器映像、GROMACS 版本、force field、Scheduler partition 與輸出路徑。
  • Skill 使用專屬非 root 身分、唯讀輸入、寫入專屬工作區、受限 egress 與短效憑證。
  • 高成本或有資料外傳風險的工作進入 approval gate；所有結果透過 Artifact Store 回傳。

RAG、知識庫與科學資料治理

ACL-first

先授權再檢索

向量查詢前根據使用者、部門、專案、資料級別與目的過濾。不得先檢索全部資料後才在回覆階段遮罩。

Provenance

每段都有來源

chunk 應保留原始文件、版本、擁有者、有效日期、雜湊、資料級別與索引時間。科學回答需回鏈到文獻／實驗或 run artifact。

Injection Defense

文件不等於指令

將 PDF、網頁、Issue、README 內的命令視為不可信內容；檢索 Rails 檢測注入語句，禁止文件文字直接改寫系統規則或觸發工具。

Freshness

版本與撤銷

索引支援到期、撤銷、重新嵌入與回溯；回答顯示版本與日期。對安全、法規與實驗 SOP 設置較短的更新檢查週期。

Palo Alto 五道防線：優化版

01

模型與 Artifact 進門前：AIRS Model Security

威脅惡意權重、pickle RCE、轉換腳本與依賴投毒。
控制掃描模型、程式碼與依賴；優先不可執行格式；建立雜湊、簽章、Model Card、SBOM 與部署准入。

02

推論與 Agent 運行時：AIRS／Guardrails

威脅Prompt Injection、資料外洩、工具濫用、越獄。
控制Input、retrieval、dialog、execution、output 多階段檢查；外加 JSON Schema、權限決策與人工核准。

03

統一進出口：AI Gateway

威脅影子 AI、外部 SaaS 外傳、Key 外洩、用量失控。
控制集中認證、模型 allowlist、DLP、rate／token／budget、模型路由、不可抵賴日誌。

04

開發供應鏈：IDE、套件、MCP、CI/CD

威脅惡意 Extension、PyPI/npm 套件、MCP Server、CI Secret。
控制端點／依賴掃描、私有鏡像、鎖版雜湊、SBOM、Secret scanning、簽章與部署政策。

05

NGFW 與零信任微分段

威脅GPU／推論節點被內網橫移與直接存取。
控制僅 Gateway／Orchestrator 可存取模型端點；HPC、管理、資料、Sandbox 分區；預設 deny egress 與異常流量告警。

供應鏈、機密與資料保護

模型／映像准入

只允許私有 Registry 中已掃描、已簽章、雜湊固定的模型與 Container Image；不可使用浮動 tag。

套件鎖版

Python/npm 使用 lockfile 與 hash；CI 建立 SBOM，掃描 CVE、惡意行為與 License；避免安裝時任意執行腳本。

Secrets

Key 不進入 Git、Image、Prompt、Notebook 與一般 log；使用 Secrets Manager、短效 Token、輪替與撤銷。

資料最小化

送進模型、RAG、工具與日誌的資料皆採最小必要集合；個資、商業機密與研究 IP 有分級、遮罩與保留期。

網路、容器與 HPC 隔離

區域 允許來源 可連線目標 禁止事項
AI Gateway 企業 App／受管使用者 核准模型 API、Guardrails、Orchestrator、SIEM 直接存取資料庫、Scheduler admin、任意外網
LLM 推論 僅 Gateway／受管 Orchestrator 必要模型儲存、監控 一般內網直連、公開 Port 8000／11434
Agent Sandbox 僅 Skill Router 特定 MCP API、Artifact Store、受管 DNS 任意 egress、host mount、privileged、Docker socket
GROMACS/HPC Scheduler／核准 Submit Skill MPI/RDMA fabric、平行檔案系統、Artifact Store 從 Web UI 直接 SSH、非核准 job、外網下載
管理平面 受管管理跳板與管理員 節點、Registry、Secrets、Policy 與一般業務流量共網段

稽核、可觀測性與 SLO

Security

安全事件

記錄 Prompt／RAG 注入阻擋、DLP 命中、越權工具請求、Sandbox policy denial、異常 egress、模型／映像准入拒絕。

Science

科學可重現性

保存 run manifest、輸入雜湊、container digest、GROMACS 版本、seed、job ID、checkpoint、輸出 artifact 與分析版本。

Reliability

服務健康度

追蹤 p50/p95 latency、首 token、queue depth、tokens/s、GPU/CPU/RAM、Sandbox 失敗率、Scheduler 排隊與 job 成功率。

Cost

配額與預算

按部門／專案追蹤 token、GPU-hours、儲存、網路與任務成本；設定警告與硬上限，防止 Agent 無限制 retry 或模擬爆量。

起始 SLO 建議

  • 高風險工具調用：100% 有身份、政策版本、核准與結果 Artifact 的可關聯事件。
  • 模型 API：設定符合業務的可用性目標；延遲應依模型／token budget 分級，避免對長推理任務承諾不合理秒數。
  • 科學任務：run manifest 完整率 100%；失敗重試有次數上限與人工升級條件。
  • 安全事件：高風險 policy denial 與疑似資料外傳在既定分鐘級目標內送至 SIEM／SOC。

驗證、紅隊與發布閘門

Agent Red Team

對抗測試

測直接／間接注入、跨角色資料取得、工具參數竄改、惡意檔案、長 context 干擾、外部 URL 與迴圈重試。

Science QA

科學工作流測試

以固定小型 benchmark 驗證 template、單位、參數範圍、容器、排程、checkpoint restart 與結果解析器。

Load Test

資源壓測

驗證 Gateway 的 rate limit、queue、timeout、模型 OOM 行為、HPC quota 與 job storm 保護。

Release Gate

阻擋上線條件

未簽章 Artifact、無法關聯日誌、越權 Skill 可成功、惡意 RAG 文件可觸發操作、回滾未演練，皆不得發布。

安全事件 Runbook

1. 偵測與分級

區分模型供應鏈、資料外洩、Prompt Injection、MCP／Skill 濫用、Sandbox 逃逸、HPC 異常作業與服務阻斷。

2. 遏制

撤銷 capability token、停用 Skill／模型版本、封鎖 Gateway route 或 egress；必要時切換為只讀、無工具模式。

3. 證據保全

保存 audit、policy、container、network、scheduler、artifact 與身份日誌，並鎖定相關雜湊與版本。

4. 根因與修補

修正權限、模板、政策、掃描規則或程式碼；輪替機密；將攻擊手法加入 regression test。

5. 恢復與檢討

從可信版本 Canary 恢復，監控復發訊號；完成含時間線、影響、根因、責任與期限的 postmortem。

上線檢核表

□ 控制面已收斂

□ 科學任務可重現

□ 供應鏈可驗證

模型、程式、MCP、依賴與映像已掃描、鎖版、簽章／雜湊驗證並建立 SBOM。

□ Sandbox 與網路最小化
