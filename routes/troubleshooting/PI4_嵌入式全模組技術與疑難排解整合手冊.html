02 1. 硬體限制與系統環境邊界說明

🔥 CPU 與熱散熱邊界

BCM2711 4 核心 Cortex-A72，長時間高負載易觸發 80°C 降頻保護 (Thermal Throttling)，必須配置主動式散熱風扇。

💾 記憶體瓶頸 (1GB RAM)

系統可用 RAM 僅約 650MB，禁止在本地載入超過 300MB 的深度學習大模型（如本地 LLM 必引發 OOM 崩潰）。

⏱️ Linux 非即時時脈誤差

標準 Linux 非即時作業系統 (Non-RT OS)，軟體計時器會有 10μs ~ 100μs 的抖動，禁止使用軟體產生 PWM。

03 2. 伺服馬達與舵機控制 (servo_module.py)

❌ 已解決之 4 大痛點與根因

  • 軟體 PWM 抽搐異音：Linux 排程誤差 ➔ 切換至 pigpio DMA 硬體 PWM (<1μs)。
  • 靜止高頻哼聲發燙：持續通電 ➔ 導入 0μs 斷電放鬆機制 (`set_pw(0)`)。
  • 順時針轉、逆時針卡死：阻力不對稱 ➔ 設計獨立啟動脈衝 (CW=40μs / CCW=55μs)。
  • 中心臨界點急啟急煞：邊界震盪 ➔ 引進雙門檻死區遲滯 (Enter=0.14 / Exit=0.18)。

🛡️ 未來開發防踩坑預警

  • ⚠️ pigpiod 前置依賴：初始化檢查 `pi.connected`，systemd 加入 `Requires=pigpiod.service`。
  • ⚠️ 嚴禁用樹莓派 5V 供舵機電：瞬間電流可達 2A，必用獨立 5V/3A 變壓器供電並共地 (GND)。
  • ⚠️ 避免 GPIO 18 與音訊衝突：音訊模式下 PWM 必須改用 GPIO 12 或 GPIO 13。

04 3. 電腦視覺與手勢動態追蹤 (hand_tracking_module.py)

現象與痛點 底層技術根因 技術修復方案與代碼實作
FPS 低於 8 幀，嚴重 Delay 誤用預設 `model_complexity=1` 且輸入解析度高達 1080P。 強制指定 model_complexity=0（Lite 模型），OpenCV 解析度設為 320x240，速度飆升至 25+ FPS。
手腕旋轉導致相機劇烈晃動 只追蹤 Node 0 (Wrist)，手掌翻轉即產生極大座標位移。 採用 5 點算術平均手掌質心（手腕 0 + 四指指根 MCP 5, 9, 13, 17）。
手部靜止時相機微幅震盪 相機感光元件噪聲導致座標小數點後三位隨機跳動。 導入一歐元低通濾波器 `OneEuroFilter` (min_cutoff=0.8, beta=0.4)，兼顧低速防抖與高速零延遲。

05 4. 離線 KWS 語音喚醒與音訊驅動

ALSA 硬體獨占衝突與修復

Linux ALSA 的 `plughw:1,0` 為硬體獨佔模式。喚醒後前台錄音搶佔聲卡會引發 `Device or resource busy` 並拋出 Exit Code 255 死循環。

  • 強制釋放與冷卻等待（0.3s）：確保切換前裝置控制權完全釋放。
  • 配置 `/etc/asound.conf` 軟體混音器：使用 `dmix` 與 `dsnoop` 模式允許多進程共享聲卡。

聲學迴音防自激機制

防止喇叭播報語音時自己喚醒自己（自言自語死循環）：

  • TTS 播報前掛起 KWS：呼叫 pause_kws() 暫停監聽。
  • 播報結束 300ms 冷卻恢復：延遲 0.3 秒後呼叫 resume_kws()。
  • USB 麥克風增益：自動以 amixer 設定 Capture 音量至 90%。

06 5. 雲端 AI 語音 (Gemini 3.5) 與 TTS 快取

Gemini 3.5 Flash-Lite 極速串接

全線切換至 gemini-3.5-flash-lite 雲端 API，記憶體佔用 < 20MB，首字回應時間縮短至 0.5 秒內，徹底避免本地大模型 OOM 崩潰。

文字 MD5 哈希語音快取

計算語音文字之 MD5 值，若 /tmp/tts_cache/{hash}.mp3 已存在則直接回傳本地路徑（0 秒延遲播報）；並設定 100MB 容量上限自動清理最舊音訊，保護 SD 卡壽命。

07 6. NFC 身份感應與 ST7789 螢幕中文

硬體模組 常見致命錯誤 黃金標準避坑實作
PN532 NFC 讀卡 使用無限阻塞讀取 (`read_passive_target`)，卡片長置時鎖死 I2C 匯流排導致程式崩潰。 設定 `timeout=0.1s` 非阻塞保護，未感應到立即釋放 I2C 控制權，並加入 0.5s 防重複刷卡去抖動。
ST7789 小螢幕 直接向 LCD 驅動發送原始 ASCII 中文字串，導致螢幕顯示方塊 □□□ 或問號。 使用 PIL (Pillow) 動態 TrueType 圖片繪製：引入 .ttf 字型在記憶體繪製 240x240 RGB 圖片再送入驅動。

08 7. STT 語音辨識與 VAD 動態收音

Gemini 多模態 Base64 直傳 + 動態能量 VAD

將錄音音訊轉換為 Base64 直接送給 Gemini 3.0+ 模型，同時以 pyaudio + audioop.rms 即時監測說話能量（閾值 350），開口自動錄、靜音超過 1.5 秒自動截止，徹底告別傳統固定秒數錄音的尷尬延遲與截斷！

09 8. 相機鏡頭棋盤格去畸變標定 SOP

廣角/魚眼鏡頭在邊緣會產生桶狀畸變，使用前必須進行一次性標定：

1. 拍攝 15~25 張 9×6 棋盤格照片

棋盤格貼在硬板上保持平整，出現在畫面左上、右上、左下、右下與中央，包含正拍與傾斜。

2. 執行標定腳本並儲存參數

使用 cv2.calibrateCamera 計算內參矩陣與畸變係數，儲存為 camera_calib.npz 供主程式 cv2.undistort 即時呼叫。

10 9. 未來開發防踩坑黃金法則

⚡ 硬體與電源檢核法則

  • 法則 1：舵機瞬間電流達 2A，嚴禁用樹莓派 5V 引腳供電，必用獨立 5V/3A 變壓器並共地。
  • 法則 2：GPIO 18 與 3.5mm 音訊衝突，使用音訊時 PWM 必改用 GPIO 12/13。
  • 法則 3：I2C 匯流排讀取（NFC/感測器）必須設定 timeout=0.1s 非阻塞保護。
  • 法則 4：通電靜止時必須傳送 0μs 方波切斷信號，防止馬達發燙。

💻 軟體與系統排程法則

  • 法則 5：Pi4 1GB 嚴禁本地跑大模型，STT 與 LLM 採雲端 Base64 直傳。
  • 法則 6：MediaPipe 必選 model_complexity=0，搭配一歐元低通濾波器。
  • 法則 7：ALSA 聲卡切換加 0.3s 冷卻，並配置 dsnoop 共享混音模式。
  • 法則 8：背景 Thread 呼叫非同步時，必用 asyncio.new_event_loop() 隔離。
