Gemini Base64 + VAD

樹莓派語音互動系統 (KWS/STT/LLM/TTS) 開發歷程與技術總結

記錄在 Raspberry Pi 4 (1GB RAM) 邊緣硬體下，建構語音助理從離線喚醒 (KWS)、動態語音辨識 (STT)、大語言模型 (LLM) 到語音合成 (TTS) 的完整踩坑與解決方案。

📌 一、 核心架構目標

  • 邊緣低延遲喚醒：1GB RAM 資源受限環境下，使用輕量離線引擎常駐監聽關鍵字「阿萬」。
  • 動態智慧收音 (VAD)：告別固定秒數錄音，開口自動錄、說完自動停（靜音超時截止）。
  • 雲端多模態直傳：對接 Gemini 3.0+ Flash 系列模型完成語音辨識與角色扮演。
  • 高容錯降級保護：斷網時避免無窮報錯與誤觸動相機/舵機。

🚨 二、 開發過程中遇到的 5 大核心困境

1
本地離線模型缺失與虛擬端點斷線

虛擬端點拋出 [Errno -2] Name or service not known，且本地 STT 缺少模型檔案導致連環報錯。

2
ALSA 硬體獨占衝突 (`Device or resource busy`)

前台錄音與背景 KWS 搶佔 plughw:1,0 聲卡，導致 Exit Code 255 無窮死循環。

3
固定秒數錄音導致體驗不佳與語音截斷

固定錄製 3.5 秒使短句需乾等、長句後半段被截斷。

4
背景 Thread 與 Asyncio Event Loop 衝突

KWS 背景執行緒呼叫 asyncio.run() 與 FastAPI 主迴圈衝突引發崩潰。

5
Gemini API 版本演進與 403/404 報錯

舊版模型名稱引發 404，預設金鑰配額被封鎖引發 403。

💡 三、 最終架構與技術解決方案

核心維度 解決方案與實作細節 關鍵檔案
STT 架構選型 Gemini 多模態 Base64 直傳：錄音轉換為 Base64 透過 REST API 送給 Gemini 3.0+ 模型辨識，節省本地記憶體。 cloud_ai_client.py
ALSA 衝突修復 強制釋放與 0.3s 冷卻，並自動備援 default 與 dsnoop:1,0 混音模式。 wake_word_module.py
動態 VAD 收音 以 pyaudio + audioop.rms 監測說話能量（閾值 350），靜音 1.5s 自動截止。 audio_module.py
執行緒與事件安全 使用 asyncio.new_event_loop() 建立獨立 loop 執行非同步流程。 main.py
金鑰與模型管理 支援 gemini-3.7-flash 與 gemini-3.5-flash-lite，並透過 .env 管理。 .env
