① 遇到問題時，先跑這個診斷流程圖

1
先確認 Python 版本：python3 --version，確認是否落在 3.9~3.12 之間（MediaPipe 官方支援區間）。
2
確認系統架構：uname -m，確認是 aarch64 還是 armv7l。
3
確認 mediapipe 是否能 import：python3 -c "import mediapipe as mp; print(mp.__version__)"。
4
確認 Tasks API 是否正常：python3 -c "from mediapipe.tasks.python import vision; print('OK')"。
5
確認模組檔案語法正確：python3 -m py_compile modules/camera_module.py。
6
確認能否 import 到你的類別：python3 -c "from modules.camera_module import CameraModule"。

② 核心重點（真正根因）：Python 版本過新

★ 真正根因！請優先檢查與修復

症狀：pip install mediapipe==x.x.x 找不到對應版本，或是只找到奇怪的版本號（如 1.0.0）。

根因：Raspberry Pi OS 若基於較新的 Debian（例如 trixie / Debian 13），會內建 Python 3.13，但 MediaPipe 官方 wheel 目前最高只支援到 Python 3.12。

診斷指令：

python3 --version cat /etc/os-release

解決方式：建立 Python 3.11 虛擬環境

sudo apt update sudo apt install -y python3.11 python3.11-venv cd ~/你的專案路徑 python3.11 -m venv venv source venv/bin/activate pip install --upgrade pip pip install mediapipe==0.10.14 python3 -c "import mediapipe as mp; print(mp.__version__)" python3 -c "from mediapipe.tasks.python import vision; print('OK')"

若 apt 找不到 python3.11：代表軟體源版本更新（如 trixie），建議改用 Bookworm 版本的 Raspberry Pi OS（原生即為 Python 3.11，相容性最穩定）。

③ 次要問題：偵測不到手掌（手刻 anchor 問題）

已被官方 API 取代，不建議手刻

症狀：log 一直顯示「未偵測到手掌」，信心分數始終低於門檻。

根因：若自行用 tflite_runtime 載入 palm_detection_lite.tflite，模型輸出的 18 個數值是「相對 anchor 的偏移量」，不是絕對座標。若沒做 SSD 2016 anchors 解碼，算出來的框座標完全錯誤。

解法（若仍要手刻）：

def generate_ssd_anchors(input_size=192): anchors = [] strides = [8, 16] anchor_counts = [2, 6] for layer, stride in enumerate(strides): grid_size = input_size // stride for y in range(grid_size): for x in range(grid_size): xc = (x + 0.5) * stride / input_size yc = (y + 0.5) * stride / input_size for _ in range(anchor_counts[layer]): anchors.append((xc, yc)) return anchors

最佳解法：直接使用上方的 Python 3.11 虛擬環境，改用官方 HandLandmarker Tasks API，完全無需手刻此層。

④ 次要問題：正規化範圍錯誤

已被官方 API 取代

症狀：即使加了 anchor 解碼，confidence 仍然平坦、沒有起伏。

根因：MediaPipe 官方模型訓練時，圖像張量正規化範圍是 [-1, 1]，但常見錯誤寫法是：

img = img.astype(np.float32) / 255.0 # ❌ 錯誤，範圍變成 [0,1]

正確寫法：

img = img.astype(np.float32) img = (img - 127.5) / 127.5 # ✅ 正確，範圍是 [-1,1]

⑤ 排查方向誤判：AES 指令集分析

排查方向合理，但非主因

症狀：懷疑官方 mediapipe pip 套件因為硬體不支援 AES-NI 而 SIGILL 崩潰。

檢查方式：

cat /proc/cpuinfo | grep aes

重要提醒：即使這個指令沒有任何輸出，也不代表這就是真正的崩潰原因！請務必先確認「② 核心重點（Python 版本）」，避免繞一大圈。

⑥ 操作疏失：檔案內容截斷

操作疏失類問題

症狀：ImportError: cannot import name 'CameraModule' from 'modules.camera_module'，但模組本身可以被 import，只是找不到類別。

根因：透過終端機貼上含中文字元的長段程式碼時，容易在某一行被截斷，導致後面的 class 定義整段遺失。

診斷指令：

python3 -m py_compile modules/camera_module.py grep -n "^class " modules/camera_module.py python3 -c " import modules.camera_module as cm print([x for x in dir(cm) if not x.startswith('_')]) "

修復方式：用 heredoc 方式覆寫或追加，避免逐行手動貼上：

cat >> modules/camera_module.py << 'EOF' # 這裡貼上遺失的完整程式碼區塊 EOF

💡 關鍵教訓心得

真正卡關的根本原因，往往不是表面看到的症狀。

這次「偵測不到手掌」背後真正的根因是系統版本（Debian trixie + Python 3.13）超前於 mediapipe 官方套件的支援範圍，而不是最初懷疑的 AES 硬體限制或 anchor 解碼邏輯。

建議排查優先順序：下次遇到類似問題，請務必先檢查 Python 版本相容性（② 核心重點），再考慮硬體限制（⑤ AES 指令集），最後才去手刻底層邏輯（③④ 手刻 Anchor / 正規化）。這樣可以省下大量排查時間。
