② 核心控制參數與邏輯規範

關鍵參數設定

  • 追蹤點：MediaPipe Landmark 0（手腕根部 WRIST）
  • 靜止基準 (STOP_PW)：1470 μs（實測完全靜止零點）
  • 死區克服量 (MIN_MOVE_PW)：40 μs（保證偏離即轉動）
  • 最高旋轉增益 (MAX_MOVE_PW)：120 μs（控制最大轉速）
  • 中央死區 (CENTER_TOLERANCE)：0.15（畫面中央總寬 30%）

控制邏輯分支

  • Node 0 進入中央 30% 綠框 ➔ 輸出 1470 μs（馬達物理靜止）
  • Node 0 偏離綠框右側 ➔ 輸出 1470 + (40~120) μs 平滑轉向
  • Node 0 偏離綠框左側 ➔ 輸出 1470 - (40~120) μs 平滑轉向
  • 未偵測到手部 ➔ 輸出 1470 μs（保持靜止防爆走）

③ 四大經典 Bug 深度根因分析與處方

1按下開始偵測，馬達即瘋狂爆走

根本原因分析：
舊邏輯在「對齊 ➔ 停止」時呼叫 pwm.stop()，在「偏離 ➔ 開始」時呼叫 pwm.start()。 RPi.GPIO 軟體 PWM 每次在 pwm.start() 重啟瞬間，都會產生一個固定方向（順時針）的初始化電壓毛刺 (Spike)。當手部在邊界頻繁微抖時，無數個重啟毛刺疊加，馬達就被誤導為全速暴力旋轉。
解法：
廢除追蹤過程中動態 start/stop 的架構！改為程式啟動時只 start 一次，整個生命週期完全只透過修改脈衝寬度控制。靜止時輸出靜止基準值，絕不關閉 PWM。

2不管切換 1 還是 -1，馬達都只朝順時針轉

根本原因分析：
1. 軟體 PWM 重啟造成的順時針毛刺蓋過了真實控制訊號。
2. 為了讓馬達轉慢，將幅度壓縮得太小（如偏離量 < 0.3%），這個變化量落在 MG90S 馬達內部電位器的機械死區 (Deadband) 內。馬達靜摩擦力無法克服，正轉動不了，只有毛刺發生時朝順時針衝。
解法：
加入死區克服基礎量 MIN_MOVE_PW = 40 μs。只要手偏離中央死區，輸出的脈衝寬度必然直接跨越死區（例：1470 + 40 = 1510 μs 或 1470 - 40 = 1430 μs），確保馬達一定能順暢雙向旋轉！

3馬達即使沒看到手也會一直「抽搐/脈動 (Twitching)」

根本原因分析：
1. 軟體 PWM 缺陷：RPi.GPIO 是用 CPU 執行緒搭配 OS 睡眠實現的。當樹莓派同時執行 OpenCV、MediaPipe、FastAPI 時，CPU 負載波動導致 OS 喚醒時間不準，脈衝產生 ±100μs 誤差，馬達收到的訊號不斷微幅微抖。
2. 靜止點校準偏差：原本用軟體 PWM 校準的靜止點為 7.10% (1420 μs)，但精確的硬體零點其實是 7.35% (1470 μs)，相差了 50μs，導致馬達在理論零點時其實一直處於微幅旋轉狀態。
解法：
1. 升級為 pigpio 硬體 DMA PWM：直接由樹莓派 DMA（直接記憶體存取）控制器產生訊號，完全不受 CPU 負載與 OS 排程影響，誤差 < 1μs。
2. 使用專門校準工具實測出真正的零點：1470 μs。

4手移到左右兩邊馬達沒反應 / 畫面突然黑屏

根本原因分析：
1. 舊版設計了過度複雜的遲滯鎖（Hysteresis），手只要進過一次死區就被鎖定為 _aligned = True，必須偏移 >30% 才能解鎖，導致大部分範圍馬達都被鎖死。
2. 程式中遺漏了 global _aligned 宣告，造成 Python 拋出 UnboundLocalError 導致 OpenCV 視訊串流崩潰（黑畫面）。
解法：
移除過複雜的狀態鎖，簡化為無狀態的單一死區判定 (CENTER_TOLERANCE = 0.15)；修復 Python 全域變數宣告。

④ 軟體 PWM vs 硬體 DMA PWM 核心差異表

比較項目 RPi.GPIO (軟體 PWM) pigpio (硬體 DMA PWM)
脈衝產生原理 Python 執行緒 + OS 睡眠 DMA 控制器 + 硬體定時器
CPU 負載影響 高負載時嚴重漂移 (±100μs) 完全不受影響 (< 1μs)
馬達表現 抽搐、抖動、發熱、脈衝毛刺爆走 極度平穩、零抖動、精確運轉
pwm.start() 影響 重啟會產生方向固定的 Spike 輸出極度乾淨，無初期毛刺

⑤ 核心控制演算法代碼精華 (Python Code)

這段是 test_tracking_web_final.py 中最精華的控制邏輯，方便未來直接移植：

# ── 核心運轉計算 (process_frame 內) ────────────────────── if tracking_enabled: if abs(offset) <= CENTER_TOLERANCE: # ── 進入 30% 死區：馬達輸出 1470us 靜止 ── target_pw = STOP_PW status = f"ALIGNED (off={offset:+.3f}) - STOP" else: # ── 偏離死區：基礎克服量 (40us) + 動態比例增益 ── ratio = min(1.0, (abs(offset) - CENTER_TOLERANCE) / (0.5 - CENTER_TOLERANCE)) add_pw = MIN_MOVE_PW + ratio * (MAX_MOVE_PW - MIN_MOVE_PW) direction = TRACK_SIGN * np.sign(offset) target_pw = int(STOP_PW + direction * add_pw) # ── pigpio DMA 安全輸出 ─────────────────────────────────── def set_pw(pw: int): global _last_pw pw_clamped = max(1000, min(2000, pw)) with _pwm_lock: if abs(pw_clamped - _last_pw) >= 2: # 變化大於 2us 才觸發 DMA 更新 pi.set_servo_pulsewidth(SERVO_PIN, pw_clamped) _last_pw = pw_clamped

⑥ 伺服馬達靜止零點校準 SOP (Calibration Guide)

日後若更換馬達或硬體，可執行我們編寫的 calibrate_pigpio.py 工具重新找靜止點：

  1. 執行校準工具：python calibrate_pigpio.py
  2. 從預設 1420 μs 開始測試，觀察馬達轉動方向。
  3. 輸入 +5 或 -5 微調脈衝寬度，直到馬達軸心完全不動。
  4. 找到完全靜止的值後輸入 q，更新回主程式的 STOP_PW。

⑧ 樹莓派機器人控制三大金律 (Key Takeaways)

💡 開發三大金律
  1. 做精確伺服/馬達控制時，永遠不要用 RPi.GPIO 的軟體 PWM：Raspberry Pi 跑 Linux 非實時作業系統，軟體 PWM 在 CPU 有負載時必然抖動。請務必使用 pigpio 或硬體 PWM 晶片（如 PCA9685）。
  2. 連續旋轉伺服馬達必須給予「死區補償 (Deadband Offset)」：馬達轉動有最小啟動脈衝門檻，計算 speed 時直接給比例值會讓小偏移無動力；必須使用 STOP_PW ± (MIN_PW + ratio * MAX_PW) 的算式。
  3. 伺服馬達 PWM 訊號保持 Session 持續輸出，切勿頻繁 Start/Stop：PWM 訊號的停止應該輸出靜止基準寬度，而非切斷 GPIO 電壓。頻繁開關只會帶來開關毛刺。
