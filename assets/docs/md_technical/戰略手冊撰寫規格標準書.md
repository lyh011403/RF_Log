# 戰略手冊撰寫規範標準書 (Strategic Document Standard Specification, SDSS v1.0)

本規範書為未來所有「公司戰略手冊」、「專案商業計劃」、「產品發展路徑」之最高準則。所有後續產出文件必須嚴格依循本規格之架構、資料深度與驗證邏輯。

---

## 壹、核心撰寫原則 (Core Principles)

1. **結論先行 (BLUF - Bottom Line Up Front)**：
   每個章節的第一段必須在 3 句話內給出核心結論、決策方向或量化數據，禁止鋪墊冗長背景。
2. **數據背書與口徑拆解 (Data-Backed & Scoped)**：
   禁止使用「市場潛力巨大」、「成本極低」等模糊語句。所有市場規模、財務預估必須明確標記「數據來源」、「統計口徑」與「悲觀/基準/樂觀」區間。
3. **主動防禦反對論點 (Devil's Advocate Integration)**：
   文檔必須主動包含「專家質疑」、「競品威脅」與「替代方案（如手機/開源替代）」，並給出硬性邏輯反駁，不迴避致命弱點。
4. **財務與單位經濟閉環 (Unit Economics Viability)**：
   任何產品策略必須拆解至單點（單店/單機/單用戶）的 LTV、CAC、BOM 成本、月運維成本與回收期（Payback Period）。
5. **模組化與可執行性 (Actionable Phasing)**：
   戰略必須拆解為具體時限（如 30/60/90 天里程碑）、交付物（Deliverables）與負責角色，且具備明確的「終止/轉向停損指標（Kill Switch）」。

## 貳、標準架構與模組規範 (Standard Module Schema)

所有戰略文檔一律由以下 **8 大核心模組** 組成，順序不得任意調換：

```
[Module 01] 執行摘要與核心定位 (Executive Summary & Positioning)
    ├── 1.1 一句話定位 (One-Sentence Value Proposition)
    ├── 1.2 核心矛盾與戰略破局點 (Core Conflict & Breakthrough)
    └── 1.3 核心決策結論表 (Key Decisions Summary Table)

[Module 02] 產品與技術能力矩陣 (Product & Tech Matrix)
    ├── 2.1 現有能力清單 (Current Assets & Tech Stack)
    ├── 2.2 核心壁壘與非對稱優勢 (Moats & Asymmetric Advantage)
    └── 2.3 技術邊界與不做清單 (Technical Boundaries & "What We DON'T Do")

[Module 03] 市場實態與真實 TAM/SAM/SOM (Market Reality)
    ├── 3.1 目標場域真實痛點 (Field Pains: 營運/人力/成本)
    ├── 3.2 市場規模多口徑對比 (Market Sizing: 悲觀/中立/樂觀)
    └── 3.3 POC 場域 vs 終極市場 (Beachhead vs End Game)

[Module 04] 致命質疑與防禦論證 (Critical Counter-Arguments)
    ├── 4.1 「市場過小/小眾」質疑之拆解與破局
    ├── 4.2 「通用替代品 (如手機/平板/軟體)」之差異化壁壘
    └── 4.3 商業轉換摩擦力 (採購意願、安裝門檻、維護負擔)

[Module 05] 商業模式與單位經濟模型 (Unit Economics & Monetization)
    ├── 5.1 營收來源組合 (Hardware / Subscriptions / Services / Data)
    ├── 5.2 單點成本拆解 (BOM + Logistics + On-site Support + Cloud API)
    ├── 5.3 客戶投資回報 (Customer ROI & Payback Calculation)
    └── 5.4 定價策略與階梯方案 (Tiered Pricing Strategy)

[Module 06] 階段執行藍圖 (Phased Execution Roadmap)
    ├── 6.1 Phase 1 (0-90天)：POC 驗證與關鍵指標
    ├── 6.2 Phase 2 (90-180天)：產品標準化與種子客戶擴張
    └── 6.3 Phase 3 (180-360天)：規模化、異業合作或技術授權

[Module 07] 風險矩陣與應變預案 (Risk Management & Kill Triggers)
    ├── 7.1 風險等級評估表 (機率 x 衝擊程度 x 緩解方案)
    └── 7.2 停損/轉向指標 (Project Pivot / Kill Criteria)

[Module 08] 決策清單與即刻行動項 (Immediate Action Items)
    ├── 8.1 關鍵決策核決 (Go/No-Go Checkpoints)
    └── 8.2 責任人分工與 14 天衝刺清單 (Sprint Backlog)
```

## 參、各模組詳細填寫規格與驗證規則 (Field Rules)

### Module 01: 執行摘要 (Executive Summary)
* **必備元素**：
  * **一句話價值主張**：`為 [目標客群] 解決 [核心痛點]，透過 [關鍵技術/方法]，達成 [量化商業價值]`。
  * **戰略定位演進**：清楚標明「當前破局點（Beachhead）」與「遠期延伸市場（Expand Market）」。
* **驗證規則**：若未能在單一表格內呈現全案核心結論，退回重寫。

### Module 02: 產品與技術能力矩陣 (Product & Tech Matrix)
* **必備元素**：
  * 技術狀態標籤：明確標註各功能為 `[已實裝] / [開發中] / [評估中] / [明確不做]`。
  * **「明確不做清單（Not-to-do List）」**：防止專案範圍蔓延（Scope Creep）。例如：「不做自由對話聊天機器人」、「不使用需要繁瑣認證之射頻模組」。
* **驗證規則**：嚴禁僅列出技術名詞（如 AI, LLM），必須說明在特定場景下之輸入、處理與輸出成果。

### Module 03: 市場實態 (Market Reality)
* **必備元素**：
  * 將痛點拆分為「經濟層面（租金/人事）」、「運營層面（排班/尖離峰）」與「體驗層面（教學/上手）」。
  * 數據表格必須採用多維度對照，明列統計來源與口徑限制。
* **驗證規則**：嚴禁將總體大市場（如全球桌遊百億市場）直接當作公司第一年可獲得市場。必須以實體店鋪數/設備台數做底層由下而上（Bottom-Up）推估。

### Module 04: 致命質疑與防禦論證 (Critical Counter-Arguments)
* **必備元素**：
  * **手機/既有方案對決表**：必須逐項列出「使用手機的代價」vs「使用專用硬體/一體機的價值」。
  * **小眾市場破局邏輯**：說明為何小眾場域能作為最快產生現金流與技術數據沉澱的 POC 沙盒。
* **驗證規則**：若未列出至少 2 個最嚴厲的外部質疑（如投資人、導師、競爭者視角），視為無效文檔。

### Module 05: 商業模式與單位經濟 (Unit Economics)
* **必備元素**：
  * **單店/單台硬體損益模型**：
    $$\text{淨回本週期 (月)} = \frac{\text{單機硬體成本 (BOM) + 獲客成本 (CAC)}}{\text{每月訂閱收入} - \text{每月雲端與運維成本}}$$
  * 必須包含客戶端 ROI 計算（例如：為店家每月節省多少工時/增加多少翻桌率）。
* **驗證規則**：所有金額必須具備明確幣別（如 TWD / USD），毛利率低於 40% 或回本期超過 18 個月需額外提出風險補償策略。

### Module 06 & 07: 執行藍圖與風險矩陣 (Roadmap & Risk)
* **必備元素**：
  * POC 驗證必須給出「可量化指標」（例如：單週穩定開機時數 > 20 小時、故障率 < 2%）。
  * 停損指標（Kill Switch）：例如「若 90 天內無法取得 3 家付費意向書，即終止硬體生產並轉向軟體授權」。
* **驗證規則**：沒有停損觸發條件的路線圖視為無效路線圖。

## 肆、格式規範與排版標準 (Formatting & Presentation Standard)

1. **視覺層次與標籤化**：
   * 採用階層式標題（H1 篇章 -> H2 模組 -> H3 核心議題 -> H4 實施細則）。
   * 善用高亮標籤：`[現狀]`、`[決策]`、`[警告]`、`[量化指標]`。
2. **比較表格化**：
   * 凡涉及方案評估、競品分析、財務預測，一律使用 Markdown 或 HTML 表格呈現，禁止大段純文字描述。
3. **程式碼與交付格式**：
   * 文檔主檔：標準 Markdown (`.md`)。
   * 呈現與匯報版：自適應、自包含單一 HTML 檔案（含夜間/日間模式、列印 CSS 優化、目錄側邊欄跳轉）。

## 伍、戰略手冊優化檢核清單 (Strategy Audit Checklist)

在文檔定稿發布前，必須通過以下 6 項審查：

- [ ] **1. 去除廢話**：是否刪除「顯而易見」、「眾所周知」、「具有重大意義」等無資訊增益之修飾詞？
- [ ] **2. 責任明確**：每個執行項目是否均指定了交付物與時程？
- [ ] **3. 數字校驗**：財務模型與市場規模數字是否前後一致、可被反推？
- [ ] **4. 防禦充分**：是否正面回答了「為什麼不能用手機做」與「市場小怎麼辦」？
- [ ] **5. 邊界清晰**：是否明確定義了「現階段堅決不做什麼」？
- [ ] **6. 停損健全**：是否設定了客觀的專案終止/轉向機制？
